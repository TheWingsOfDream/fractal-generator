一个零依赖的单文件分形渲染器。浏览器打开即用，支持 Mandelbrot 与 Julia 集，WebGL2 硬件加速，可放大到 10¹² 量级。



---

## 特性

| | |
|---|---|
| **单文件零依赖** | 一个 HTML，无构建、无 CDN、无 npm，双击即用 |
| **双引擎** | WebGL2 片元着色器（毫秒级）与 float64 CPU（支持 10¹² 深度放大），按浮点精度自动切换 |
| **距离估计着色** | 用 `d = \|z\|·ln\|z\|/\|z'\|` 估计到边界的距离，而非迭代次数——边缘有立体光晕，无色带断层 |

| **流畅交互** | 滚轮以光标为锚缩放、拖拽平移；拖动时用上一帧做几何变换过渡，不重算 |
| **一键导出** | PNG 导出，Chrome / Edge 支持自选保存目录 |

## 技术说明

### 1. 为什么用距离估计而不是迭代次数

Mandelbrot 集的定义是"迭代 `z ← z² + c` 永不逃逸的 `c` 集合"。由于"永不"无法验证，常规做法是设迭代上限，把"第几步逃逸"映射成颜色。

但直接使用整数迭代次数会产生同心色带；即便用平滑公式插值，在集合尖点这类梯度极陡的位置仍会出现可见的假断层——这是数据的真实高梯度被放大成视觉断层，换任何配色都消不掉。

本项目的做法是同时迭代导数 `z' ← 2zz' + 1`，用

```
d = |z| · ln|z| / |z'|
```

估计该像素到集合边界的距离。距离场天然连续，边缘因此获得立体光晕，且不会出现等势线断层。代价是每次迭代多几次乘法，CPU 路径约慢 40%。

### 2. 双引擎与精度边界

两条路径算法完全一致，差别只在浮点宽度：

| 引擎 | 精度 | 1800×1200 / 迭代 800 | 适用跨度 |
|---|---|---|---|
| WebGL2 片元着色器 | float32 | 约 10~50 ms | `span > 3.2e-4` |
| CPU 单线程 | float64 | 3~8 s | 直到 `span = 1e-12` |

阈值不是写死的常数。float32 在 `c ≈ 0.78` 处的可表示间隔为 `2⁻²⁴ ≈ 6×10⁻⁸`，要求每像素至少跨 3 个间隔，则

```
minSpan = ulp32 × 宽度 × 3,   ulp32 = 2^(floor(log₂|c|) − 23)
```

中心坐标移远时 ulp 变大，阈值随之翻倍，故必须运行时计算。

实测两条路径的差异（Node 模拟 float32）：

| 场景 | ΔRGB | 说明 |
|---|---|---|
| `span = 4.2` | 0 | 完全一致 |
| `span = 1e-3` | 1 | 一致 |
| `span = 1e-5` | 292 | 精度崩溃，两条路径得出完全不同的迭代结果 |

最后一行正是自动回落机制存在的理由：低于阈值时 GPU 不是"略糊"，而是算错了。

### 3. 渐进渲染的调度

代价在于"参数一变就要重画，但重画要几秒"。解法是分级：

| 触发 | 响应 | 耗时 |
|---|---|---|
| 参数变化 | 预览级 16×16 采样，一帧内成图 | 约 12 ms |
| 停手 260 ms | 自动细化至全分辨率 | 3~8 s |
| 拖拽 / 滚轮 | 上一帧画面做几何变换，不重算 | 3~5 ms/帧 |

`requestAnimationFrame` 合并同一帧内的多次输入，`setTimeout` 每次重置——只要还在操作，完整渲染就不触发。

## 已知限制

- **GPU 路径受 float32 精度约束**：放大超过约 1.3 万倍后自动回落 CPU，速度降为秒级。强制 GPU 会在更深缩放时出现块状伪影。
- **深度放大需手动提高迭代上限**：`span` 每缩小一个数量级，边界附近的点往往需要更多迭代才能判定。上限 50000。
- **集合内部的小岛是真实结构**：深层放大后，螺旋空隙中的深色斑点经 50 万次迭代复判确认为集合的连通分量（mini-Mandelbrot），并非渲染缺陷，因此予以保留。
- **触摸屏未做双指缩放**：目前仅支持单指拖拽。
- **CPU 路径为单线程**：尚未使用 Web Worker，仍有 4~6 倍提速空间。
